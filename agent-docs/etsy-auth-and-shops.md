# Etsy: авторизация, магазины, сервера

## Магазины и где крутится парсер
| `shop_id` в CMS | Магазин | Где парсер |
|---|---|---|
| 1 | NikoEngraving | Второй хост (в разное время — ноутбук клиента в Лос-Анджелесе); уточнять перед работой |
| 2 | AldaProduction | там же |
| 3 | DaDaTeamEngraving | `31.172.69.164`, контейнер `souvtech-parser-1` |
| 4 | ElmaVadaStudio | там же |
| 5, 6 | Ebay, Amazon | парсера нет, магазины заведены только для склада |

Конфиги магазинов по серверам лежат в корне воркспейса: `parsers-config-dada-elma.json`,
`parsers-config-niko-alda.json` (формат `data/shops/shops.json`). Один процесс парсера
обслуживает магазины из своего `shops.json`; `parser_id` там = id записи в таблице `parser` CMS.

## `data/shops/shops.json` — единственное состояние парсера
Список `ShopData`: `parser_id`, `shop_id`, `shop_name`, `etsy_shop_id` (строка),
`shop_token`, `shop_refresh_token`, `expiry` (unix ts), `shop_auth_code`, `shop_cookie`
(legacy, не используется). Папка `data/` не в git и примонтирована в контейнер как `/app/data`.
Парсер **пишет** в этот файл при обновлении токена. Чтение/запись обёрнуты в `threading.Lock`
(`utils/json_file_handler.py`, запись через временный файл), но read-modify-write в
`_save_auth_token` не атомарен: два потока, обновляющих токены одновременно, могут затереть
друг друга (TODO в `parser.py`). Не добавляй ещё писателей этого файла.

## OAuth-флоу (`src/etsy_api/get_etsy_api.py`, `constants/etsy_oauth.py`)
- Библиотека `etsyv3`; `SouvTechEtsyAPI` переопределяет `refresh()`: `client_id` — часть
  `ETSY_API_KEY` до `:`, после обновления токены сохраняются в `shops.json`.
- Если у магазина нет токенов: печатается ссылка на consent Etsy, процесс ждёт по 60 с, пока
  в `shops.json` не появится `shop_auth_code`. Код после согласия прилетает на
  `ETSY_API_REDIRECT_URL` (webhook на pipedream) и вставляется в файл руками.
  `src/auth_code_endpoint.py` для этого не работает (сломанный импорт).
- Scopes только на чтение. `code_verifier` и `state` — константы для всех магазинов.
- `get_etsy_api()` вызывается на **каждый** запрос к Etsy и делает `time.sleep(3)` — это
  фактический ограничитель скорости.

## Лимиты Etsy
Бесплатный ключ: 10 000 запросов в сутки, 10 в секунду (клиенту озвучивали 5000/5).
4 магазина × 1 запрос в минуту ≈ 5.8k в сутки плюс обновления токенов и недельная догрузка.
Поэтому: не сокращать минутный цикл, не добавлять запросы на заказ (картинки листингов
отвергнуты именно из-за лимита), новые магазины считать по бюджету.

## Что нельзя делать
- Запускать парсер или `get_etsy_api()` с машины разработчика: токены живут на сервере,
  а `get_etsy_api()` может обновить токен и перезаписать `shops.json` параллельно с рабочим
  парсером. Для разовых проверок — `backend/agent-docs/etsy-api.md`.
- Логировать/печатать токены в новых местах (в `refresh()` они уже пишутся в лог на
  уровне `success` — это известная проблема, не множить).
- Менять `data/` в git: он игнорируется намеренно.
